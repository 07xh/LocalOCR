# 自训练模型部署闭环设计与验收门禁

> 状态：Paddle 静态图导出代码已接入实验性 CLI，仅使用模拟导出测试；ONNX 转换、兼容性评测、热切换/回滚仍待实施。不能将“微调得到权重”或“已经登记模型”等同于“可在 RapidOCR 中运行”。

## 保留现有结构

- `training.py`：继续使用**外部** PaddleOCR/PaddlePaddle Python 环境，训练与主进程轻量推理分离。
- `models.py`：延伸现有只读 ModelRegistry；用明确状态记录导出、兼容性、自有测试集评估与启用结果。
- `engine.py`：保留默认 RapidOCR 引擎；增加验证后自定义识别模型实例，不修改检测与方向分类默认模型。
- `api.py`：仍仅监听回环地址、要求 API Key；任何部署/回滚操作必须显式调用，不自动启用模型。
- `studio.js`：继续作为本地标注/训练准备工作台，在验收后再增加模型对比与回滚入口。

## 目标管道

1. **产物核验**：仅允许 `completed` 任务登记的 `.pdparams`，检查大小、哈希、训练配置、字典和相关本地路径。
2. **Paddle 静态图导出**：由训练外部 Python 调用与当前 PP-OCRv5 mobile-rec 配置匹配的官方 `tools/export_model.py`；保存日志和退出码，不下载不可信权重。
3. **转 ONNX**：锁定与 Paddle 导出格式兼容的 `paddle2onnx` 版本；导出 ONNX 后用 ONNX Runtime 创建会话、验证输入输出结构、字符字典长度，并通过真实识别小样本烟测。不能只按扩展名判定兼容。
4. **模型对照评估**：在训练/验证完全隔离的 `reviewed_test` 样本上，用**同一批次**对照默认模型与候选模型的 CER、整行精确匹配、空预测数、P50/P90 时延；评测过程禁止修改标签。密集图先扩展区域游标以解决 40 个区域的硬上限。
5. **显式切换 + 自动回滚**：实例预热成功、性能/质量门禁通过，或用户明确确认警告后，才原子切换为自定义识别模型；保存旧实例以便出错、服务重启或质量下降时回滚。切换必须可审计，默认始终为自带模型。
6. **Windows 真实封板**：从实际 `.pdparams` 经 Paddle 导出、ONNX Runtime 加载、RapidOCR 推理、对照评测、启用/回滚，在 Windows 10/11 上完整跑通并记录日志。

## 尚未实现

- 官方 Paddle v5 静态图导出：已增加基于已登记模型的 CLI、检查点 SHA-256 和状态校验以及模拟子进程测试；真实 Paddle 导出仍待 CI/Windows 验证。**尚未实现** `paddle2onnx` 转换和训练字典可靠匹配。
- 自定义 ONNX 推理实例的初始化/热切换；包括并发推理时切换的一致性。
- 完整 `reviewed_test` 的模型间公平对照与区域游标。
- 不同系统与不同版本 RapidOCR 的兼容性测试。
- 真实中文/英文、表格与复杂手机截图的独立评测。

### 验收标准

最少包括成功闭环、错误 ONNX 拒绝、字典不兼容拒绝、损坏权重拒绝、评测失败不切换、并发推理中切换不崩溃、启用后可一键回滚、进程重启默认安全模型。没有这些测试不得称作“模型热部署完成”。
